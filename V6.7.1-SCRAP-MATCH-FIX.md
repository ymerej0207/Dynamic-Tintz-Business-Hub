# Dynamic Tintz OS v6.7.1 — Scrap Match Fix

Fixes scrap matching/reservation when multiple identical cutoffs and multiple
identical job windows exist.

Your test case:
- 4 × 34x40 25% Ceramic scraps
- 4 × 34x29 25% Ceramic scraps
- Job: 4 × 34x39 and 4 × 34x28

Expected result: 8 scrap matches, 0 fresh-roll pieces.

Changes:
- Scrap optimizer now considers Available scraps plus scraps already Reserved to the SAME quote.
- Scraps reserved to other quotes remain excluded.
- Matching is deterministic and processes the most constrained/largest windows first.
- Saving a plan reserves every unique matched scrap ID without filtering out same-quote reservations.
- Optimizer status now reports how many eligible scraps were checked and how many matched.

No SQL migration.
No Edge Function deployment.

Replace app.js, index.html, styles.css, service-worker.js.
