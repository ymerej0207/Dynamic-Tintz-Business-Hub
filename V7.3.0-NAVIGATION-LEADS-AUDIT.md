# Dynamic Tintz OS v7.3.0 — Navigation Audit + Lead Center Fix

ROOT CAUSE FOUND
The v7 app navigation had an authorization bug:
allowedView() only considered buttons physically present in the five-button bottom nav.

That meant pages located under More were treated as unauthorized even for the owner.
Leads, Follow-Ups, Roll Optimizer, Responses, Team, and Account could all bounce back to Home.

FIX
- Role-based page access is now independent of visible bottom-navigation buttons.
- All owner pages were audited against actual HTML view IDs.
- All routed pages were audited against their page loader references.
- Navigation now uses delegated routing so dynamically rendered links remain functional.
- Leads is now a PRIMARY bottom tab because it is operationally critical.
- Bottom nav: Home | Leads | Quotes | Schedule | More
- Inventory moved to the first position inside More.
- More: Inventory, Follow-Ups, Roll Optimizer, Responses, Team, Account.
- Home data-go shortcuts and app links use the same router.
- A navigation audit runs after sign-in and reports missing pages in console.

LEAD CENTER
Lead cards now show, inside Dynamic Tintz OS:
- Lead source
- Phone / email / location
- Project Request (service_requested)
- Angi Description / Customer Message (original_message)
- Attempt count / follow-up timing
- Call, Copy Phone, Log Attempt, Create Quote, Delete

If an Angi customer typed a description, it is visible directly on the lead card.
No need to open Angi to read the customer's submitted request.

IMPORTANT
This does NOT change the v6.9 customer-facing Square privacy behavior.
Angi/internal data stays visible inside Dynamic Tintz OS but is not inserted into the
customer-facing Square invoice description.

No SQL migration.
No Edge Function deployment.

Replace:
- app.js
- index.html
- styles.css
- service-worker.js
