# Dynamic Tintz OS v6.8.1 — Calendar Status Policy Fix

This fixes duplicate calendar events when a job is marked Completed.

Calendar behavior is now intentionally limited by job status:

- Scheduled  -> sync/create/update calendar event
- Confirmed  -> sync/create/update calendar event
- Canceled   -> delete/remove calendar event
- In Progress -> NO calendar action
- Completed   -> NO calendar action
- Rescheduled -> NO calendar action

Most importantly, marking a Scheduled job Completed no longer calls the calendar
sync function, so it cannot create a second calendar event.

The existing scheduled calendar appointment is left in place as historical record
when the job is Completed.

Canceled explicitly removes the calendar event.

This policy is used both from Schedule & Assign Job and from the Operations Board
so the two screens cannot behave differently.

No SQL migration.
No Edge Function deployment.

Replace:
- app.js
- index.html
- service-worker.js

styles.css is unchanged but included for convenience.
